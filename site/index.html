What I work on

Four things, and the numbers behind them

I build the control planes that run databases. Go and Kubernetes at the bottom, PostgreSQL internals at the top, consensus and replication in between — everything between provisioning a cluster and getting it back after a datacenter dies.

Kubernetes operator engineering

Go controllers, CRDs and admission webhooks that teach Kubernetes to run stateful workloads it was never designed for — including a fork of the StatefulSet controller that places pods across geo-distributed, multi-cloud clusters.

733 PRs across 100+ repositories

PostgreSQL lifecycle ownership

The whole arc as declarative API calls instead of runbooks: provisioning, configuration tuning, vertical and horizontal scaling, major-version upgrades, TLS and credential rotation, WAL archiving and point-in-time recovery.

PostgreSQL 13 → 18 · 8 Day-2 operations

High availability and disaster recovery

Raft leader election with WAL positions propagated over gRPC, synchronous quorum replication spanning datacenters, and a control plane that promotes a surviving site without waiting for a human to notice the outage.

Failover in 2–10 seconds

Operating it at scale

Consistent-hash sharding so a single control plane reconciles the whole fleet in parallel, verified with bulk-provisioning benchmarks and deliberate fault injection rather than assumed to work.

2000+ clusters · 16+ chaos experiments

A database that fails over in seconds is not the same product as one that fails over when somebody notices. Losing the primary should be boring.
